# Lab 12 — FastAPI ML Service
21_04_2026

## Цель работы
Разработать простой сервис для развёртывания модели машинного обучения с использованием **FastAPI**.

В рамках работы было выполнено:
- создание FastAPI-приложения,
- обучение модели машинного обучения,
- загрузка модели при старте приложения,
- создание маршрутов API,
- описание входных данных через **Pydantic**,
- получение предсказания через POST-запрос,
- вывод информации о модели и метрик качества,
- запуск сервера локально,
- проверка работы API через Swagger-документацию.

---

## Используемые технологии

- **FastAPI** — создание API-сервиса  
- **Pydantic** — описание и проверка входных данных  
- **scikit-learn** — обучение модели машинного обучения  
- **LogisticRegression** — модель классификации  
- **Wine dataset** — встроенный датасет sklearn  
- **Uvicorn / FastAPI dev** — запуск локального сервера  

---

# Эксперименты

## 🔹 Exp1 — Создание FastAPI приложения

На первом этапе было создано приложение FastAPI.

Был добавлен главный маршрут:

- GET /

Он возвращает сообщение о том, что сервис работает, и ссылку на документацию API.

**Результат:**
- Сервер успешно запущен
- Главная страница доступна по адресу http://127.0.0.1:8000
- Swagger-документация доступна по адресу http://127.0.0.1:8000/docs

**Вывод:**  
FastAPI-приложение было успешно создано и запущено локально.

---

## 🔹 Exp2 — Обучение ML-модели

На втором этапе была обучена модель машинного обучения на датасете **Wine**.

Для классификации использовалась модель **LogisticRegression**. Перед обучением признаки масштабировались с помощью **StandardScaler**.

**Результат:**
- Shape X: (178, 13)
- Shape y: (178,)
- Shape X_train: (142, 13)
- Shape X_test: (36, 13)
- Accuracy: 0.9722  

**Вывод:**  
Модель показала высокое качество классификации. Accuracy на тестовой выборке составила 0.9722.

---

## 🔹 Exp3 — Загрузка модели при старте приложения

На третьем этапе была реализована загрузка и обучение модели при запуске FastAPI-приложения.

Для этого был использован механизм **lifespan**, который выполняет код при старте и остановке приложения.

**Результат:**
- Модель обучается автоматически при запуске сервера
- Метрики модели сохраняются в глобальные переменные
- API сразу готов к обработке запросов после старта

**Вывод:**  
Механизм lifespan позволил подготовить модель до начала обработки пользовательских запросов.

---

## 🔹 Exp4 — Маршруты API

На четвертом этапе были реализованы основные маршруты API.

Были добавлены маршруты:

- GET /
- GET /api/model/info
- GET /api/model/metrics
- POST /api/predict

**Результат:**
- GET / возвращает базовую информацию о сервисе
- GET /api/model/info возвращает информацию о модели
- GET /api/model/metrics возвращает метрики качества
- POST /api/predict возвращает предсказанный класс и вероятности

**Вывод:**  
API позволяет получить информацию о модели, посмотреть метрики и выполнить предсказание по входным данным.

---

## 🔹 Exp5 — Pydantic и предсказание класса

На пятом этапе была создана Pydantic-модель для входных данных.

Модель **WineRequest** описывает 13 признаков объекта Wine. Эти признаки передаются в POST-запросе на маршрут:

- POST /api/predict

**Результат:**
- Входные данные проверяются автоматически
- Swagger показывает пример JSON-запроса
- Сервис возвращает predicted_class_id, predicted_class_name и probabilities

**Вывод:**  
Pydantic упростил описание структуры входных данных и сделал API удобным для тестирования через Swagger.

---

## 🔹 Exp6 — BackgroundTasks

На шестом этапе было добавлено логирование предсказаний через **BackgroundTasks**.

После выполнения предсказания результат записывается в файл:

- prediction_log.txt

**Результат:**
- Предсказание возвращается пользователю сразу
- Запись в лог выполняется в фоновом режиме

**Вывод:**  
Фоновые задачи позволяют выполнять дополнительные действия без блокировки основного ответа API.
